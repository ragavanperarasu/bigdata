## 1. Domain Selection and Challenges

**Domain**: E-commerce (Retail)

In a large-scale e-commerce platform (like Amazon or Flipkart), the company deals with massive volumes of data generated by millions of users interacting with millions of products.

### Key Challenges:
1. **Data Volume**: Billions of clickstream events, views, and transactions per day make traditional relational databases insufficient.
2. **Data Sparsity**: Most users only interact with a tiny fraction of the available product catalog, making it hard to find similarities.
3. **Data Velocity**: User preferences change rapidly (e.g., seasonal trends), requiring the system to process and update recommendations quickly.
4. **Cold Start Problem**: New users or new products have no historical interaction data, making it difficult to provide initial recommendations.

------------------------------------------------------------------------

## 2. Data Science Strategy

To solve these challenges, we apply the standard Data Science Process:

| Step | Activity | Application to E-commerce Solution |
| :--- | :--- | :--- |
| **1** | **Business Understanding** | Goal: Increase Average Order Value (AOV) and reduce churn by showing products the user is likely to buy. |
| **2** | **Data Acquisition** | Collect UserID, ProductID, and interaction type (purchase=5, add-to-cart=3, view=1) from HDFS. |
| **3** | **Data Preprocessing** | Remove bot-generated traffic, handle missing values, and cast IDs to integers. |
| **4** | **Exploratory Data Analysis** | Identify "Power Users" (high interaction) and "Best-Sellers" to establish baselines. |
| **5** | **Modeling** | Use **Collaborative Filtering (ALS)** to predict missing ratings based on user-item similarity. |
| **6** | **Evaluation** | Measure the **Root Mean Square Error (RMSE)** between predicted and actual ratings. |
| **7** | **Deployment** | Push the top-10 recommendations per user to a fast-access NoSQL store for the frontend API. |

# 3. Implementation (PySpark MLlib)

We implement a recommendation engine using the Alternating Least Squares (ALS) algorithm, utilizing the MovieLens ratings dataset as a proxy for real-world user-item interactions.

*Note: If you are using the `pyspark` interactive shell, the `spark` session is already created. You can skip the SparkSession builder block.*

``` python
from pyspark.sql import SparkSession
from pyspark.ml.recommendation import ALS
from pyspark.ml.evaluation import RegressionEvaluator
from pyspark.sql.functions import col

# Initialize Spark Session (Optional in PySpark Shell)
spark = SparkSession.builder \
    .appName("EcommerceRecommendation") \
    .config("spark.executor.memory", "4g") \
    .getOrCreate()

# 1. Load Real-World Dataset
# Using MovieLens ratings as user-item interactions (userId, movieId/productId, rating)
data_path = "file:///home/kavimugil-r/Desktop/Big Data/MoveisLens-DataSet/ratings.csv"
df = spark.read.csv(data_path, header=True, inferSchema=True)

# Rename movieId to productId for e-commerce context
df = df.withColumnRenamed("movieId", "productId")

# 2. Train-Test Split
(training, test) = df.randomSplit([0.8, 0.2], seed=42)

# 3. Build ALS Model
# coldStartStrategy="drop" ensures we don't get NaN for users not in training set
als = ALS(userCol="userId", itemCol="productId", ratingCol="rating", 
          coldStartStrategy="drop", nonnegative=True)
model = als.fit(training)

# 4. Evaluation
predictions = model.transform(test)
evaluator = RegressionEvaluator(metricName="rmse", labelCol="rating", predictionCol="prediction")
rmse = evaluator.evaluate(predictions)
print(f"Root Mean Square Error (RMSE): {rmse}")

# 5. Generate Actionable Insights: Top 5 recommendations for all users
user_recs = model.recommendForAllUsers(5)
user_recs.show(truncate=False)

spark.stop()
```

# Common Errors

## NaN Predictions
If the model predicts `NaN`, it's usually due to the "Cold Start" problem. 
**Solution**: Set `coldStartStrategy="drop"` in the ALS constructor to remove predictions for users/items not present in the training set.

## Divergence in Training
If the RMSE is extremely high or increasing, the model might be diverging.
**Solution**: Tune the `regParam` (regularization) to prevent overfitting.
